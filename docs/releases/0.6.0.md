# Jev Java 0.6.0

Adds OpenAI Decisions GA support to the existing `jev-openai` adapter.
Java 17 remains the minimum runtime. Provider defaults remain unchanged.

## OpenAI Decisions GA

- Shared input accepts JSON objects/arrays, developer/system/assistant messages,
  and historical function/custom-tool calls and outputs. The SDK does not
  execute tools or interpret JSON fields as instructions or image references.
- Images may use inline base64 or hosted HTTP(S) URLs. The SDK sends URLs to
  OpenAI without downloading them. Native question instructions accept ordered
  text/image/JSON parts through `DecisionQuestion.*.multipart(...)` factories.
- `DecisionCacheOptions` and the request builder expose cache keys, implicit or
  explicit modes, 30-minute TTL and explicit text/image input breakpoints.
  Cache fields are omitted unless set; reported cache tokens are already part
  of input-token totals.
- Generic `evaluate` and record APIs accept JSON state and structured question
  instructions, including generated `@JevLabels` instructions. Choice
  descriptions and Score levels retain their documented text limitations.
- Validation covers 1–400 questions, 128 aggregate images, Choice 2–255 options,
  Score 2–10 levels, and JSON limits of 32 container levels, 10,000 values and
  256 KiB of compact UTF-8 JSON. Binary Java/Jackson values nested in JSON
  become detached base64 strings.

OpenAI Box remains unsupported. Organization usage reporting, GPT-Live session
configuration and Private Link provisioning are separate platform surfaces;
see the [OpenAI guide](../openai-decisions.md) for scope and examples.

## Compatibility

Existing constructor/accessor signatures and `Messages`/`UserMessage`
iteration are retained. Java record components and sealed input/part variants
have expanded: reflection, record patterns and exhaustive switches may need
updates. Multipart questions return null from the legacy `instructions()`
accessor; use `instructionParts()` for their content. Requests now reject
Choice/Score counts outside the official bounds before HTTP, even when built
with legacy constructors. Other providers' question limits are unchanged.

Native refusals remain individual results; generic refusals fail the evaluation.
Cancellation, deadlines, retry policy and caller-owned transport behavior remain
unchanged. Hosted images are fetched by OpenAI, not by this SDK.

## Verification and limits

486 offline tests pass with Spring Boot 3.5.16 and 4.1.1 on OpenJDK 25,
compiling for Java 17. Release/Javadoc packaging, all three OpenAI guide Java
blocks, and a consumer compiled against published 0.5.0 artifacts were checked.
Independent critic review found JSON binary handling and provider-count gaps;
regression tests and a third review closed both findings.

A single Java SDK call with synthetic JSON/history and a generated image
returned HTTP 429 / RATE_LIMIT. Its provider error code was not inspected.
Successful GA inference and cache hits remain unverified; the historical
October 7 billing error does not establish the cause of this request.
Offline fixtures establish contract behavior, not inference accuracy.

See [validation](../validation.md) and the [official Decisions guide](https://developers.openai.com/api/docs/guides/decisions).
